# CampusPass

CampusPass is an Android-based campus event management and digital ticketing application designed to simplify how students discover, register for, and attend events on campus.

The application provides students with a central platform for viewing upcoming events, registering for events, accessing QR-based digital tickets, and managing their CampusPass profile and preferences.

For event organisers, CampusPass provides tools for managing event attendance and validating student tickets through QR code scanning.

The project consists of two repositories:

- `campuspass-app` — Android mobile application
- `campuspass-api` — Custom REST API and database backend

---

## Project Overview

Campus events are often advertised and managed across multiple disconnected platforms. This can make it difficult for students to discover events, register efficiently, and access their tickets when attending.

CampusPass provides a centralised solution where students can:

- Sign in securely
- Browse campus events
- Search and filter events
- View detailed event information
- Register for events
- Access digital tickets
- Display QR tickets for entry
- Manage their profile and settings

Organisers can use CampusPass to:

- Manage campus events
- View events they organise
- Scan student QR tickets
- Validate tickets against the backend
- Prevent the reuse of already scanned tickets
- Track event attendance

### Event Registration

Event registration is performed through the CampusPass API.

When a student registers for an event, the backend verifies conditions such as:

- Whether the event exists
- Whether the event has been cancelled
- Whether the student is already registered
- Whether event capacity has been reached
- Whether the user is allowed to register

Successful registration creates a digital ticket associated with the student and event.

## Digital Tickets

Registered students can access their CampusPass tickets from the application.

Each ticket is linked to:

- A student
- An event
- A unique ticket ID
- A unique QR code
- A ticket status

QR ticket images are generated by the backend and returned to the Android application for display.

This ensures the backend remains the authoritative source for ticket information.

---

## QR Ticket Validation

CampusPass uses QR codes for event entry validation.

The Android application uses ZXing Embedded to scan QR codes.

A CampusPass QR payload contains information in the following format:

```json
{
  "ticketId": 1,
  "eventId": 1,
  "qrCode": "unique-ticket-code"
}
```

After scanning a QR code:

1. The Android application reads the QR payload.
2. The ticket ID is extracted.
3. The application sends the ticket ID to the protected attendance API.
4. The backend verifies the ticket.
5. The backend records attendance if the ticket is valid.
6. The ticket is marked as used.
7. A previously used ticket cannot be scanned successfully again.

This provides server-side validation instead of relying only on information contained inside the QR code.

---

## Attendance Validation

Attendance is recorded using:

```http
POST /api/attendance/scan
```

Example request:

```json
{
  "ticketId": 1
}
```

The attendance endpoint is protected and restricted to authorised organiser accounts.

The backend validates:

- Ticket existence
- Ticket status
- Event ownership/authorisation
- Whether the ticket has already been used

After successful validation, an attendance record is created and the ticket status is updated.

## Offline Support

CampusPass includes local Room database support for event caching.

When online, events retrieved from the REST API can be synchronised with the local Room database.

If remote event retrieval is unavailable, cached event information can be used to support offline event browsing.

The local data layer contains:

- Room database
- Event entity
- Event DAO
- Synchronisation manager

This allows the application to retain useful event information when network connectivity is interrupted.

# Running CampusPass

## Prerequisites

Install:

- Android Studio
- Android SDK
- JDK 17
- Node.js
- npm
- Git

Clone both the Android application and API repositories.

---

## 1. Start the CampusPass API

Navigate to the API project:

```powershell
cd C:\Users\<YOUR_USERNAME>\AndroidStudioProjects\campuspass-api
```

Install dependencies if required:

```powershell
npm install
```

Configure the required environment variables in the API `.env` file.

> The `.env` file is intentionally excluded from Git and must not be committed.

Start the API using the command configured by the backend project, for example:

```powershell
npm start
```

Confirm that the API is running on the configured local port.

The development configuration used during integration testing exposed the API on:

```text
http://127.0.0.1:3000/api/
```

---

## 2. Connect Android to the Local API

When testing with an Android emulator/device through ADB, reverse port `3000`:

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" reverse tcp:3000 tcp:3000
```

The Android application can then access:

```text
http://127.0.0.1:3000/api/
```

Ensure the Retrofit base URL matches the backend configuration.

---

## 3. Build the Android Application

Navigate to:

```powershell
cd C:\Users\<YOUR_USERNAME>\AndroidStudioProjects\campuspass-app
```

Build the project:

```powershell
.\gradlew.bat assembleDebug
```

A successful build should finish with:

```text
BUILD SUCCESSFUL
```

The application can then be launched through Android Studio.

### QR Validation Testing

During development, QR camera integration and backend ticket validation were verified separately.

The QR scanner successfully launches through the Android application.

The backend attendance endpoint was separately tested with a valid generated ticket and successfully:

- Accepted the valid ticket
- Created an attendance record
- Marked the ticket as used

## Known Development Limitations

The local SQLite database is excluded from Git source control. Developers therefore need to initialise or create their own local development data when setting up the backend on another machine.

Physical-device QR scanning is recommended for final end-to-end QR demonstrations because webcam passthrough may behave unpredictably inside virtualised emulator environments.

Features requiring external platform configuration, such as third-party authentication or notification services, may require the relevant local credentials/configuration on each development machine.
